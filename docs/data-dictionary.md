# Data Dictionary — ShowMine Dataset

This document defines every field in the dataset, how it is generated, and how it is used in each mining technique.

---

## Raw Dataset (`data/raw/tv_shows.csv`)

847 rows × 17 columns, generated by `backend/src/generate_dataset.py`.

| Column | Type | Range / Values | Description |
|---|---|---|---|
| `id` | int | 1–847 | Unique show identifier |
| `name` | string | — | Unique show title (suffix added if duplicate) |
| `primary_genre` | categorical | see Genres table | Main genre classification |
| `secondary_genre` | categorical | see Genres table or empty | Optional secondary genre |
| `network` | categorical | see Networks table | Broadcasting or streaming platform |
| `year` | int | 2000–2024 | Year the show premiered |
| `seasons` | int | 1–14 | Number of seasons produced |
| `episodes_per_season` | int | 4–26 | Average episodes per season |
| `total_episodes` | int | 4–364 | `seasons × episodes_per_season` |
| `avg_runtime_min` | int | {22, 30, 44, 50, 60} | Average episode length in minutes |
| `imdb_rating` | float | 1.0–10.0 (clipped) | IMDb-style quality rating |
| `popularity_score` | float | 1.0–100.0 | **Primary target variable** — composite popularity index |
| `vote_count` | int | 500–2,500,000 | Number of audience ratings |
| `status` | categorical | Ended / Ongoing / Cancelled / Limited Series | Current show status |
| `language` | categorical | English (dom.), Korean, Spanish, … | Primary broadcast language |
| `country` | categorical | USA (dom.), UK, South Korea, … | Production country |
| `cast_size` | int | 4–18 | Number of main cast members |

## Engineered Features (`data_pipeline.py`)

These are derived from the raw columns and used in modelling.

| Feature | Source | Formula / Logic | Used In |
|---|---|---|---|
| `popularity_label` | `popularity_score` | Low (0–33), Medium (34–66), High (67–100) | Apriori transactions |
| `network_type` | `network` | Streaming / Broadcast / Cable/Int'l | Regression dummies, Apriori |
| `decade` | `year` | `floor(year/10)*10 + "s"` | Apriori transactions |
| `log_votes` | `vote_count` | `log1p(vote_count)` | Clustering (scaling), Regression |
| `longevity` | `seasons` | Long-Running (≥5) or One-Season (=1) | Apriori transactions |

## Network Categories

Networks are grouped into three structural types for modelling.

| Type | Networks |
|---|---|
| **Streaming** | Netflix, HBO Max, Amazon Prime, Apple TV+, Disney+, Hulu, Peacock |
| **Broadcast** | NBC, CBS, ABC, Fox, The CW |
| **Cable/Int'l** | AMC, FX, Showtime, HBO, USA, TNT, Bravo, MTV, Syfy, BBC, BBC Two, Channel 4, Sky Atlantic, ARD |

Note: HBO appears in both HBO and HBO Max (counted separately). HBO (the cable channel) is classified as Cable/Int'l; HBO Max as Streaming.

## Target Variable: `popularity_score`

`popularity_score` is the primary regression target. It represents a composite popularity index on a 0–100 scale.

**Generation formula (conceptual):**

```
base_popularity = Normal(genre_mean, genre_std)
streaming_boost = Normal(8, 4)  if streaming platform
quality_boost   = (imdb_rating - 6.5) × 3 + Normal(0, 2)

popularity_score = clip(base_popularity + streaming_boost + quality_boost, 1, 100)
```

This intentionally creates:
- Genre-level differences in expected popularity
- A platform premium for streaming shows
- A positive but noisy correlation with quality (IMDb rating)
- Enough residual variance for the regression to be non-trivial

## Apriori Transaction Schema

Each show becomes a basket of string items for Apriori. Full item vocabulary:

| Item prefix | Example | Count |
|---|---|---|
| `genre:` | `genre:Drama` | 17 possible |
| `net:` | `net:Streaming` | 3 possible |
| `network:` | `network:Netflix` | 21 possible |
| `pop:` | `pop:High` | 3 possible (Low/Medium/High) |
| `decade:` | `decade:2010s` | 3 possible (2000s/2010s/2020s) |
| `longevity:` | `longevity:Long-Running` | 2 possible (conditional) |

A show with `primary_genre=Drama`, `secondary_genre=Thriller`, `network=Netflix`, `popularity_score=85`, `year=2021`, `seasons=3` produces:

```
["genre:Drama", "genre:Thriller", "net:Streaming", "network:Netflix",
 "pop:High", "decade:2020s"]
```

## Clustering Feature Space

K-Means operates on 4 features (after StandardScaler normalisation):

| Feature | Role in clustering |
|---|---|
| `imdb_rating` | Quality axis — distinguishes critical darlings from mass-appeal shows |
| `popularity_score` | Reach axis — primary popularity dimension |
| `log_votes` | Engagement depth — separates truly popular from technically high-rated |
| `seasons` | Longevity — separates long-running network shows from limited-run streaming originals |

`imdb_rating` and `popularity_score` together define the 2D space shown in the dashboard scatter plot. `log_votes` and `seasons` provide the additional dimensions that allow the algorithm to separate clusters that would overlap on a 2D projection.

## Regression Feature Matrix

~28 columns fed to the Random Forest after one-hot encoding:

| Feature group | Columns | Notes |
|---|---|---|
| Numeric | `imdb_rating`, `vote_count`, `log_votes`, `year`, `seasons`, `total_episodes`, `avg_runtime_min`, `cast_size` | 8 columns |
| Genre dummies | `genre_Drama`, `genre_Comedy`, … | 17 columns |
| Network type dummies | `net_Streaming`, `net_Broadcast`, `net_Cable/Int'l` | 3 columns |

`vote_count` and `log_votes` are both included. The RF can choose which representation is more useful for each split — in practice it strongly prefers `log_votes`.

## Sample Size Note

The dashboard's Show Explorer table displays a **150-show sample** from the full 847, drawn with `random_state=42`. The clustering scatter plot displays a **200-show sample** for visual clarity (all 847 points would overlap heavily). All reported statistics (cluster sizes, regression metrics, rule frequencies) are computed on the full 847-show dataset.
